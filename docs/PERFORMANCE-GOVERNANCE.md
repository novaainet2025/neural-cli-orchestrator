# NCO 목표·성과·최종지휘 운영체계

## 지휘 원칙

- 최종 주권과 의사결정권은 인간 사용자에게 있다.
- 운영 총지휘는 `org_nova-ax`의 `Commander·두뇌` 계층이 맡는다.
- 총지휘 점검은 상태를 기록하고 보고하는 비파괴 감사다. 회사·팀·태스크를 임의로 삭제하거나 비활성화하지 않는다.

## 자동 목표와 보고

모든 활성 회사와 활성 팀은 `Asia/Seoul` 기준으로 아래 세 주기의 자동 목표와 성과보고를 각각 하나씩 가진다.

| 주기 | 기간 키 | 자동 실행 | 목표 |
|---|---|---|---|
| 매일 | `YYYY-MM-DD` | 매시 정각 갱신, 매일 00:10 롤오버 | 팀 완료 1건, 회사 활성팀 실행 증거 100% |
| 매주 | ISO `YYYY-Www` | 매주 월요일 00:15 롤오버 | 상시팀 완료 5건·수요팀 1건, 회사 100% |
| 매월 | `YYYY-MM` | 매월 1일 00:20 롤오버 | 상시팀 완료 20건·수요팀 4건, 회사 100% |

자동 목표는 `team_goals.source='performance-governance'`, 자동 성과보고는
`performance_reports.source='performance-governance'`로 구분한다. 같은 대상·주기·기간에는
한 건만 존재하며 반복 실행은 현재값과 근거를 갱신한다. 지난 기간의 목표는 방향과
목표값을 기준으로 `met` 또는 `missed`로 확정한다.

## KPI 정의

- 목표 달성률: 증가형 목표는 `min(현재값 / 목표값, 100%)`.
- 태스크 성공률: `completed / (completed + failed + timed_out + 실제 실행 후 lease_expired)`.
- 업무보고 제출률: 기간 내 `due_at`이 있고 `waived`가 아닌 보고 중 제출된 비율.
- 회사 실행 커버리지: 활성 소속팀 중 기간 내 완료 태스크가 하나 이상 있는 팀의 비율.
- 취소 태스크와 `team_id`가 없는 태스크는 팀·회사 실행 지표에서 제외한다.

각 자동 보고서의 `metrics_json`에는 기간 범위, 시간대, 분모, 제외 조건, 원천 테이블,
생성 시각, 현재 격차와 다음 행동이 함께 저장된다.

## 최종 지휘관 감사

`pg-hourly-commander-audit`가 매시 5분에 다음을 점검한다.

- 활성 회사·팀의 일/주/월 목표 및 성과보고 전체 커버리지
- 최근 24시간 실패·시간초과 태스크
- 2시간 이상 정체된 활성 태스크
- 오늘 누락되거나 기한을 넘긴 업무보고
- 목표·보고·감사 예약 5개의 등록, 활성화, 시간대, 최근 실행 상태와 주기별 신선도
- 회사 관리자, 팀장, 팀 헌장, 실행팀 없는 회사

목표·보고 누락, 자동화 이상, 정체 태스크는 `fail`이다. 최근 실패나 보고 누락,
구조 보완 항목은 `attention`이다. 감사 결과와 판정 근거는
`commander_operation_audits`에 저장한다.

## 조회와 수동 검증

- 대시보드: `GET /performance-flow`
- 차트 데이터: `GET /api/performance-flow?period=daily|weekly|monthly`
- 총지휘 감사: `GET /api/commander/operations`
- 즉시 재계산과 감사: `POST /api/performance-governance/run`

대시보드는 목표 → 실행 → 성과보고 → 총지휘 점검 흐름, 목표 달성률과 태스크 성공률
그래프, 같은 수치의 접근 가능한 근거 표를 제공한다. 자동 이력이 짧을 때는 없는
과거를 추정하지 않고 실제 생성된 기간만 표시한다.
