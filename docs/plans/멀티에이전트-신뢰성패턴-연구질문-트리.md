# 설계 노트 — 멀티에이전트 오케스트레이션 신뢰성 패턴 3가지 (연구질문 분해)

- **작성일**: 2026-07-22
- **NCO 단계**: `stage=discussion/design` (진입점 · 리서치 기획·전략)
- **회사 목표**: "멀티에이전트 오케스트레이션 신뢰성 패턴 3가지 조사·정리"
- **산출물 유형**: 순수 텍스트 설계 노트 (코드 diff 0 = 사양). 하위 5개 팀 착수 전 범위 확정용.
- **후속 소비자**: 탐색팀 · 수집팀 · 분석팀 · 검증팀 · 집필/리포팅팀 (핸드오프 §5)

> 이 노트는 "무엇을 조사할지"를 확정하는 문서다. "조사 결과"가 아니다.
> 패턴 후보의 근거·출처는 이후 수집팀이 채운다. 여기서 사실을 지어내지 않는다.

## 0. 스코프 경계 (MECE 상위 프레임)

목표 문장을 세 개의 상호배타적·전체포괄(MECE) 축으로 분해한다. 세 축은 순차 의존한다:

| 축 | 질문 | 산출 | 다음 축에 넘기는 것 |
|---|---|---|---|
| **RQ1 후보군 정의** | 어떤 패턴들이 "멀티에이전트 오케스트레이션 신뢰성 패턴" 범주에 드는가? | 후보 롱리스트(N개) + 각 1줄 정의 | 판정 대상 집합 |
| **RQ2 판정 기준** | 후보를 "신뢰성 패턴"으로 인정·비교하는 기준은 무엇인가? | 판정 루브릭(가중치 포함) | 채점 척도 |
| **RQ3 3종 선정** | 롱리스트를 루브릭으로 채점해 상위 3개를 고르는 근거는? | 최종 3종 + 채점표 + 탈락 사유 | 정리·집필 대상 |

- **상호배타**: RQ1=집합 정의, RQ2=척도 정의, RQ3=선택. 후보·기준·선택이 겹치지 않는다.
- **전체포괄**: "무엇을(후보) / 어떻게 잴지(기준) / 무엇을 고를지(선택)" 3단이면 조사 파이프라인이 end-to-end로 닫힌다.
- **경계 밖(명시적 제외)**: 실제 구현·벤치마크 실행, NCO 코드 수정, 특정 벤더 제품 비교. 이번 산출물은 "연구질문 패키지"까지다.

## 1. RQ1 — 패턴 후보군 정의

**연구질문**: 멀티에이전트/분산 오케스트레이션에서 "신뢰성(=실패에도 정확·완주)"을 높이는 것으로 알려진 조율 패턴은 무엇인가? 각각을 한 줄로 정의하라.

**후보 롱리스트 (수집팀 조사 대상 · 순서는 우선순위 아님):**

| # | 패턴 | 1줄 정의(가설적 · 수집팀 검증 대상) | 대응하는 실패모드 |
|---|---|---|---|
| C1 | **재시도 + 백오프** (Retry/Backoff) | 일시적 실패를 지수 백오프·지터로 재시도 | 일시 오류·레이트리밋·네트워크 순단 |
| C2 | **멱등성** (Idempotency) | 동일 요청 재실행이 부작용을 중복시키지 않음(멱등 키) | 재시도·중복 전달로 인한 이중 실행 |
| C3 | **합의/투표** (Consensus/Voting/Quorum) | 다수 에이전트 결과를 표결로 수렴, 소수 오류 흡수 | 단일 에이전트 환각·오답 |
| C4 | **서킷 브레이커** (Circuit Breaker) | 연속 실패 시 회로 차단해 폭주·전파 방지 | 다운스트림 장애 폭주·연쇄 붕괴 |
| C5 | **체크포인트/되감기** (Checkpoint/Rewind) | 중간 상태 저장 후 실패 지점부터 재개 | 장기 작업 중단·컨텍스트 유실 |
| C6 | **타임아웃/데드라인** (Timeout/Deadline) | 상한 시간 후 강제 종료·재라우팅 | 무응답 hang·좀비 워커 |
| C7 | **데드레터/보상 트랜잭션** (DLQ/Saga) | 실패 작업 격리·역보상으로 일관성 복구 | 부분 실패의 정합성 붕괴 |
| C8 | **하트비트/라이브니스** (Heartbeat/Liveness) | 주기 신호로 워커 생존 감지·페일오버 | 죽은 워커에 계속 배분 |
| C9 | **페일오버 체인/리라우팅** (Failover/Reroute) | 오프라인·리밋 워커를 대체 워커로 우회 | 특정 프로바이더 다운·리밋 |

**성공기준(RQ1 완료 판정):**
- (a) 각 후보에 **명확한 1줄 정의**가 있다.
- (b) 각 후보에 **대응 실패모드**가 1개 이상 매핑된다.
- (c) 후보 간 **중복·포함관계**를 식별해 명시한다 (예: C7 Saga ⊃ 부분적으로 C2 멱등성).

**가설 H1**: 후보군은 "재시도류(C1·C2·C6) / 합의류(C3) / 격리·복구류(C4·C5·C7) / 생존·라우팅류(C8·C9)"의 4개 클러스터로 수렴한다. → 최종 3종은 서로 다른 클러스터에서 나와야 커버리지가 넓다(중복 회피).

## 2. RQ2 — 신뢰성 판정 기준 (루브릭)

**연구질문**: 후보를 "신뢰성 패턴"으로 인정하고 상호 비교하려면 어떤 척도로 채점해야 하는가?

**판정 루브릭 (각 0~3점, 가중 합산):**

| 기준 | 설명 | 가중치 | 3점 기준(만점) |
|---|---|---|---|
| **K1 정의 명확성** | 패턴의 의도·구조·적용조건이 모호하지 않음 | ×2 | 트리거·동작·해제조건이 형식적으로 기술됨 |
| **K2 출처 등급(T1)** | 근거가 T1 지상진실(표준문서·논문·1차 코드/RFC)에 닿음 | ×3 | 1차 출처 2건 이상, URL·식별자 확보 |
| **K3 재현 가능한 실패모드 대응** | "이 실패를 이 패턴이 막는다"를 재현 시나리오로 보일 수 있음 | ×3 | 실패 재현 절차 + 패턴 적용 전/후 관측 차이 기술 가능 |
| **K4 오케스트레이션 적합성** | 단일 프로세스가 아닌 다중 에이전트 조율 맥락에 직접 적용됨 | ×2 | NCO식 다중 프로바이더 시나리오에 매핑됨 |
| **K5 독립성** | 다른 선정 후보와 실패모드가 겹치지 않음(클러스터 상이) | ×1 | H1의 4클러스터 중 미선점 클러스터 |

**총점 = Σ(점수×가중치)**, 만점 = (3×2)+(3×3)+(3×3)+(3×2)+(3×1) = **33점**.

**성공기준(RQ2 완료 판정):**
- (a) 5개 기준이 서로 **직교**(같은 것을 두 번 재지 않음)한다.
- (b) 각 기준에 **0/1/2/3 채점 루브릭**이 문장으로 정의된다.
- (c) **T1 출처 등급(K2)**을 최우선 가중(×3)으로 두어, 근거 없는 "유명한 패턴"의 과대평가를 억제한다.

**가설 H2**: K2(T1 출처)와 K3(재현 가능성)이 실질 변별력을 가진다. 정의 명확성(K1)은 대부분 후보가 고득점이라 변별력이 낮을 것 → 동점 시 K2>K3 순 타이브레이크.

## 3. RQ3 — 3가지 선정 근거

**연구질문**: RQ1 롱리스트를 RQ2 루브릭으로 채점했을 때 상위 3개는 무엇이며, 왜 나머지는 탈락하는가?

**절차(수집·분석팀 실행):**
1. C1~C9 각 후보에 K1~K5 채점 → 33점 만점 환산.
2. **클러스터 중복 제약(K5·H1)** 적용: 같은 클러스터에서 2개 이상 상위권이면 최상위 1개만 진출, 나머지는 차순위 클러스터에 양보.
3. 상위 3개 확정 + 각 **탈락 후보 1줄 사유** 기록.

**성공기준(RQ3 = 최종 산출물 완료 판정):**
- (a) 최종 3종 각각이 **정의 명확성·T1 출처·재현 가능한 실패모드 대응**(=목표 문장의 3대 성공기준)을 **모두** 충족.
- (b) 3종이 **서로 다른 클러스터**에서 선정(커버리지 폭 확보, H1).
- (c) **채점표 전체**(9후보×5기준)와 **탈락 사유**가 공개돼 선정이 재현 가능.
- (d) 각 패턴에 **최소 1개 재현 실패 시나리오**(실패 유발→패턴 적용→관측 차이)가 딸려 있음.

**가설 H3 (잠정 · 채점 결과로 검증/기각):** 최종 3종은 서로 다른 클러스터에서 다음이 유력하다 —
- 재시도류 대표: **C2 멱등성**(C1 재시도의 안전 전제이므로 상위)
- 합의류 대표: **C3 합의/투표**(NCO의 consensus 모드와 직결, T1 자체 코드 근거 확보 용이)
- 격리·복구류 대표: **C4 서킷 브레이커** 또는 **C5 체크포인트/되감기** 중 T1 근거가 강한 쪽

> H3는 **선정 결과가 아니라 예측**이다. 실제 3종은 채점표(RQ3-a~c)로 결정된다. 수집팀은 이 예측에 끌려가지 말 것.

## 4. 가설 요약 & 반증 조건

| ID | 가설 | 반증(기각) 조건 |
|---|---|---|
| H1 | 후보군이 4개 클러스터로 수렴 | 어떤 후보가 4클러스터 어디에도 안 들어가거나, 클러스터가 5개 이상 필요 |
| H2 | K2·K3가 주 변별력, K1은 낮음 | 채점 후 K1 분산이 K2·K3보다 큼 |
| H3 | 최종 3종 = 멱등성·합의·(서킷/체크포인트) | 채점 상위 3이 다른 조합 → H3 기각·실제 결과 채택 |

## 5. 탐색·수집팀 핸드오프 스펙

하위 5개 팀의 착수 범위. 각 팀 산출물은 다음 팀 입력이 된다(중복·누락 방지).

### 5.1 탐색팀 (Discovery)
- **입력**: RQ1 후보 롱리스트(C1~C9) + H1 클러스터 가설.
- **작업**: 각 후보의 표준·문헌 **1차 출처 위치**를 찾는다(막다른 조사 아님, 위치 확보만). 후보 누락(롱리스트에 없는 10번째 패턴)이 있으면 추가 제안.
- **출력**: 후보별 출처 후보 URL/식별자 리스트(등급 미판정). 신규 후보 제안 목록.
- **완료 기준**: 각 후보에 조사 착수점 ≥1개.

### 5.2 수집팀 (Collection)
- **입력**: 탐색팀의 출처 후보 리스트.
- **작업**: 각 출처를 열어 **정의·실패모드·적용조건**을 발췌. 출처 등급(T1/T2/…)을 판정해 기록.
- **출력**: 후보별 근거 카드 {정의, 실패모드, 출처 URL, 등급}. **없으면 '미확인' 표기(지어내지 말 것)**.
- **완료 기준**: 각 후보 K1·K2 채점에 필요한 원자료 확보 또는 '미확인' 확정.

### 5.3 분석팀 (Analysis)
- **입력**: 수집팀 근거 카드.
- **작업**: RQ2 루브릭(K1~K5)으로 9후보 채점 → 33점 환산. 클러스터 중복 제약 적용. 상위 3 도출 + 탈락 사유.
- **출력**: 9×5 채점표 + 최종 3종 초안 + 탈락 1줄 사유표.
- **완료 기준**: RQ3-a·b·c 충족하는 채점표.

### 5.4 검증팀 (Verification)
- **입력**: 분석팀 채점표 + 최종 3종.
- **작업**: 각 3종에 **재현 실패 시나리오**(실패 유발→패턴 적용→관측 차이) 1개씩 작성·점검. T1 출처 등급 재확인(K2 과대평가 감사). 채점 재현성 스팟체크.
- **출력**: 3종별 재현 시나리오 + 출처 등급 감사 결과 + 채점 검증 코멘트.
- **완료 기준**: RQ3-d 충족(각 3종 재현 시나리오 ≥1) + T1 근거 확정.

### 5.5 집필·리포팅팀 (Writing/Report)
- **입력**: 검증팀이 통과시킨 3종 + 근거 + 재현 시나리오.
- **작업**: "신뢰성 패턴 3가지 조사·정리" 최종 보고서 집필(정의·근거·실패모드 대응·NCO 적용 포인트).
- **출력**: 최종 보고서(markdown) 1건.
- **완료 기준**: 3종 각각 목표 3대 성공기준(정의·T1·재현) 충족이 본문에서 추적 가능.

### 5.6 핸드오프 불변식 (중복·누락 방지)
- 후보 집합은 **RQ1에서만** 바뀐다(탐색팀 신규 제안은 RQ1로 되돌려 재승인). 하류 팀이 임의로 후보를 추가·삭제하지 않는다.
- 채점 척도는 **RQ2에서만** 정의된다. 분석팀이 기준을 즉흥 변경 금지.
- '미확인'은 유효한 값이다. 데이터 공백을 추정치로 메우지 않는다(허위 보고 금지).

## 6. 파이프라인 완주(end-to-end) 검증 포인트

루프엔진이 이 스펙을 end-to-end로 통과했는지 확인하는 게이트:

- [ ] G1: RQ1 후보 롱리스트 ≥ 3, 각 1줄 정의 + 실패모드 매핑 존재.
- [ ] G2: RQ2 루브릭 5기준 × 0~3 채점 정의 + 가중치 확정.
- [ ] G3: 탐색→수집→분석→검증→집필 핸드오프 5구간 입출력 정의 완료(§5).
- [ ] G4: 각 구간 '완료 기준'이 관측 가능(다음 팀이 착수 가능한지로 판정).
- [ ] G5: 최종 3종이 목표 3대 성공기준(정의·T1·재현)에 **역추적 가능**하도록 RQ3 성공기준이 배선됨.

> 위 G1~G5는 **이 설계 노트 자체**가 충족한다(§1~§5 존재). 실제 조사 결과의 완주는 하위 5팀 실행 후 재평가.
