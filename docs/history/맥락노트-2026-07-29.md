# NCO 맥락노트 — 2026-07-29 (nvidia 퇴출 · 프로바이더 모듈화)

> 이 문서는 2026-07-29 세션에서 NCO 백엔드에 일어난 일과 그 판단 근거를 남긴 것이다.
> 개선 조치의 상세는 `docs/self-improve/provider-modularization-2026-07-29.md`.

---

## 1. 배경 — 왜 이 작업이 시작됐나

사용자 지시: **"nvidia NCO에서 퇴출한다. 모든 관련 코드 의존성, 환경변수, md문서,
옵시디언 문서에서 nvidia를 제거한다. 모두 다 찾아서 철저히 제거하고 검증한다."**

`nvidia`(NVIDIA NIM API)는 Type C(API 기반) 프로바이더로 Reasoner 역할을 맡고 있었다.
등록 위치: `config/ai-providers.json`, DB `agents` 행, 12개 팀의 lead, 33개 팀 멤버십,
`nco-government` 회사의 manager, Nova 정부 justice 부처 공직.

## 2. 실행 범위와 두 갈래 처리

작업 착수 전 실측한 nvidia 언급 규모:

| 표면 | 규모 |
|---|---|
| NCO 저장소(tracked) | 378 파일 |
| Obsidian vault | 3,145 파일 (그중 2,754가 자동 생성 저널) |
| `~/.claude` + `nova-fleet-config` | 14 파일 |
| 라이브 DB | 설정행 7개 테이블 + 과거기록 약 2만 행 |

**두 갈래로 나눈 이유.** 라이브 설정에서 nvidia를 지우는 것과 과거 보고서에서
nvidia를 지우는 것은 성격이 다르다. 보고서의 "`nvidia/code` 성공률 50.0%,
평균품질 40.50" 같은 문장에서 토큰만 삭제하면 수치의 주어가 사라져 **사실이
왜곡된 문서**가 남는다. 그래서:

- **라이브 표면(동작을 결정하는 것) = 삭제**
  `ai-providers.json`, `failover-chains.json`, `.env`, `src/` 라우팅 테이블,
  DB 설정행, 훅·커맨드, `db/hnsw-indices/nvidia.hnsw`(4.5MB 벡터 인덱스)
- **문서·기록 = `retired-provider` 로 치환**
  저장소가 이미 쓰던 용어(company-orchestrator 테스트의 `'retired-provider'`)를
  차용해, nvidia 문자열은 사라지되 문장·표·수치의 주어는 유지되게 했다.

**DB 과거 실행기록은 건드리지 않았다.** `tasks`(2,559) · `work_events`(8,535) ·
`agent_actions`(4,827) 등 약 2만 행. 사용자가 열거한 범위(코드/환경변수/md/옵시디언)에
DB 행이 없었고, 이 행들은 team-scorer의 입력이자 참조무결성 대상이다.

## 3. 의도적으로 남긴 nvidia 문자열

NVIDIA는 **GPU 벤더**이기도 하다. 이 둘을 구분하지 않으면 무관한 기능이 깨진다.

| 위치 | 내용 | 남긴 이유 |

| `docs/history/맥락노트-2026-04-09.md`, vault 마켓플레이스 | `NVIDIA GeForce RTX 4090`, `A100 80GB` | 하드웨어 스펙 기록 |
| `nova-fleet-config/docs/nco-autonomy-axis-2026-07.md` | `Voyager 패턴 (NVIDIA, 2023)` | 논문 출처. 지우면 인용 위조 |
| vault 저널 1건 | `fetchNvidiaModelOptions` | nova-cli의 실재 심볼. 치환하면 허구 심볼 생성 |
| `db/migrations/098_retire_nvidia_provider.sql` | `WHERE id='nvidia'` | 삭제 대상을 지목해야 하므로 문자열 필수 |

## 4. 작업 중 발견한 계약 (086 마이그레이션)

nvidia를 팀에서 빼자 테스트 3건이 깨졌다. 그 과정에서 **명문화되지 않은 계약**이 드러났다:

1. 헌정 5개 회사(`nco-command/evolution/engineering/assurance/government`)의
   **manager는 서로 달라야 한다** → nvidia 자리에 opencode를 넣자 evolution과 충돌
2. `teams.lead`는 **반드시 그 팀의 `team_members` 중 하나**여야 한다
   → 멤버를 지우고 lead만 바꾸면 위반
3. 팀당 **정확히 3명**의 프로바이더 멤버 → 멤버를 삭제만 하면 2명이 됨
4. command/build/verification/constitution 팀의 **lead 4개가 서로 달라야 한다**

따라서 올바른 처리는 "멤버 삭제"가 아니라 **"그 팀에 없는 다른 프로바이더로 교체"**였다.
최종 배정: `nco-government` manager → `hermes`, 팀 lead → 각 팀의 기존 멤버,
Nova 정부 justice → `hermes`, tier-policy `information` → `[opencode, hermes]`.

## 5. 작업 중 스스로 잡은 오류 3건 (적용 전 포착)

1. **서드파티 코드 오염 직전** — 일괄 치환 dry-run이 `.venv-mlx/`의
   `huggingface_hub` 소스(`nvidia.py`, `hf_api.py`)까지 대상에 넣었다.
   가상환경·site-packages 제외 규칙 추가 후 재실행.
2. **빈 백업** — vault 3,145파일 백업 tarball이 0 entry였다(cwd 리셋으로 tar 실패).
   entry 수를 세어 확인하지 않았으면 롤백 수단 없이 3,000개 파일을 고칠 뻔했다.
3. **한국어 조사 누락** — `\bnvidia\b`가 `nvidia는`/`nvidia의`에 매칭되지 않아
   1,251건이 조용히 남았다(한글이 `\w`라 경계가 성립 안 함). 라틴 문자 기준
   경계로 교체.

## 6. 두 번째 지시 — 프로바이더 모듈화

nvidia 퇴출이 41개 파일 수작업이었다는 사실 자체가 문제로 드러나, 후속 지시가 내려졌다:
**"프로바이더를 모듈화하여 쉽게 추가·삭제할 수 있도록, 추가·삭제 시 관련 의존성과
관련 코드에 모두 적용될 수 있도록."**

핵심 발견: `adaptive-scorer.ts`의 cold-start prior에 `copilot`,
`tier-policy.ts`의 WORKER_TIER에 `aider` — **둘 다 config에 없는 유령 id**였다.
하드코딩 테이블이 프로바이더 목록과 이미 어긋나 있었다.

조치는 `docs/self-improve/provider-modularization-2026-07-29.md` 참조.
요약: `src/core/provider-registry.ts`에 라우팅 해석 계층을 두어
**추가 = config에 넣으면 끝, 삭제 = config에서 지우면 끝**이 되게 했고,
`npm run provider:add|remove` CLI와 드리프트 감시 테스트를 붙였다.
