## 진행 중 이슈

1. **운영 의존성 취약점 15건이 하루 동안 그대로 유지** — 전일과 건수·패키지 목록이 완전히 동일하다. 감사 결과가 보고에는 반영되고 있으나 실제 조치로 이어지지 않고 있다는 뜻이며, 이것이 현재 가장 큰 미해결 항목이다.
2. **`axios` 계열 취약점 집중** — 프로토타입 오염, 프록시(NO_PROXY) 우회, 본문·응답 크기 제한 우회 항목이 단일 패키지에 다수 몰려 있다. `@mendable/firecrawl-js`가 이를 전이로 물고 있으며, 다행히 파괴적 변경 없이 해결 가능한 그룹에 속한다.
3. **게이트웨이 스택 취약점(`fastify`, `find-my-way`, `fast-uri`, `form-data`)** — NCO 게이트웨이가 `:6200`에서 외부 요청을 처리하므로 노출면과 직접 관련되나, 해당 취약 경로가 실제 요청 처리 경로에서 도달 가능한지는 이번에도 코드 레벨로 확인하지 못했다(전일과 동일한 미검증 항목).
4. **`@opentelemetry/*` 3건은 주 버전 상향이 필요** — 파괴적 변경 없이 처리되는 그룹과 분리해서 별도 회귀 계획이 필요하다.
5. **최근 7일 실패성 작업 84건, 완료율 25.7%** — 완료율은 전일 보고의 25.0%보다 소폭 높아졌으나 여전히 낮다. 실패 원인 분류(리밋·게이트 거부·인프라·실제 실패), 작업별 상세 상태, 담당 영역(security/audit)과의 대응 관계는 제공된 데이터에 없어 확인할 수 없다.
6. **codex/code 성공률 46.7%, 평균 품질 46.27** — opencode/code(80.8%, 68.47) 대비 현저히 낮다. 또한 세 건의 성과 요약 수치가 전일 보고와 완전히 동일한데, 이것이 그 사이 신규 실행이 없었기 때문인지 요약 집계가 갱신되지 않은 것인지는 제공된 데이터만으로 구분할 수 없다.
7. **팀 기반 모델 retired-local-provider의 지표 부재** — 팀 기반 모델은 retired-local-provider인데 제공된 성과 요약에는 opencode/codex만 있고 retired-local-provider 항목이 없다. 이 수치가 본 팀 작업을 어느 범위까지 대표하는지 확인할 수 없다.

1. 파괴적 변경 없이 해결 가능한 11건을 별도 브랜치에서 적용하고, `npx vitest run src/security`와 프로젝트 전체 테스트로 회귀를 확인한 뒤 반영 여부를 판단한다. (승인 없이 의존성 갱신을 본 브랜치에 적용하지 않는다.)
2. 주 버전 상향이 필요한 4건(`@anthropic-ai/sdk`, `@opentelemetry/*` 3건)은 변경점 문서를 확인해 호출부 영향 범위를 먼저 산정한다. `@opentelemetry/*` 3건은 `@opentelemetry/sdk-node` 갱신 한 건으로 동시 해소되는지 확인한다.
3. 게이트웨이 스택 취약점 4건에 대해 해당 취약 경로가 NCO 실제 요청 처리 경로에서 도달 가능한지 코드 레벨로 확인한다. 도달 불가로 판명되면 위험도를 하향 기록한다. (이 항목은 이틀 연속 미착수 상태이므로 우선순위를 올린다.)
4. 실패성 작업 84건의 작업명·실패 원인·재시도 여부를 수집해, 본 팀 담당 영역과 무관한 인프라성 실패를 분리한다.
5. retired-local-provider 프로바이더 기준 실행 지표를 별도 수집하고, 성과 요약 수치가 전일과 동일한 원인(신규 실행 없음 / 집계 미갱신)을 구분한다.
6. 업무보고 미제출 4건의 대상 일자와 사유를 확인한다.
7. `npm audit --omit=dev`와 `npx vitest run src/security`를 상시 임무의 고정 절차로 계속 유지해, 매 보고마다 동일 기준으로 수치를 비교한다. 보안 모듈 테스트 건수 증가(28건 → 70건)의 출처도 함께 기록한다.
