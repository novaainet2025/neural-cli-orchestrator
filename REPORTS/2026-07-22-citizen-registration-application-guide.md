# Nova 시민 등록·KYC Level 2 신청 실무 보고서

> 보고서 기준일: 2026-07-22 (KST)
> 적용 기준: `CITIZEN REGISTRY v2.1 Parameters` 및 이전 단계 검증·팩트체크 산출물 중 통과한 클레임만 사용
> 증거 수준: [Evidence Tier 1] 정책 파일 내용 및 사용자 제공 검증 산출물 확인
> 인용 방식: `[S1]`은 프로젝트 정책 원문, `[V1]`은 2026-07-22 제공된 검증 산출물을 뜻한다. 상충 자료 `[C1]`은 정책 근거로 사용하지 않았다.

## 1. 경영진 요약

- 이 보고서의 실무 대상은 Nova 시민 등록 과정에서 KYC Level 2 확인을 받으려는 신청자다. 별도의 제품별 대상 구분이나 예외는 확인되지 않았다. `[S1 §2, 기준일 2026-07-22]`
- 핵심 자격은 유효한 Verifiable Credential(VC) 3개 이상을 준비하고, 그중 최소 2개 범주를 Education·Governance·Employment에서 구성하는 것이다. `[S1 §2, 기준일 2026-07-22] [V1, 기준일 2026-07-22]`
- 확인된 절차는 `VC 3개와 해당 시 수수료 증빙 제출 → KYC Level 2 검증 → 등록 확인`의 3단계다. `[V1, 기준일 2026-07-22]`
- KYC Level 2의 유효기간은 180일이며 만료 전 30일 이내에 갱신해야 한다. 기한 내 갱신하지 않으면 Level 1으로 강등된다. `[S1 §2, 기준일 2026-07-22]`
- 수수료는 신규 등록 0 NVC, DID 변경 재등록 1 NVC, 365일을 초과해 비활성 상태였던 계정의 재활성화 2 NVC다. 정기 KYC 갱신 자체의 수수료는 원문에서 확인되지 않았다. `[S1 §3, 기준일 2026-07-22]`
- 접수 채널, 담당 부서·문의처, 심사 처리기간, 보완 기한은 확인되지 않았다. 신청 전 운영 주체에 반드시 확인해야 한다. `[V1 미확인 항목 및 S1 기재 부재, 기준일 2026-07-22]`

## 2. 상세 본문

### 2.1 제도의 목적과 대상

정책 원문은 시민 등록의 KYC Level 2 조건을 정하지만 제도의 목적을 별도 문장으로 규정하지 않는다. 따라서 공식 목적은 **미확인**이며, 본 보고서는 목적을 추정해 확장하지 않는다. `[S1 §2, 기준일 2026-07-22]`

확인 가능한 적용 대상은 다음과 같다.

| 신청 상황 | 확인된 기준 | 적용 범위의 한계 |
|---|---|---|
| 신규 시민 등록 | 최초 등록 수수료는 0 NVC다. `[S1 §3, 기준일 2026-07-22]` | 제품별·등급별 예외는 미확인이다. |
| KYC Level 2 확인 | VC 3개 이상과 지정 3개 범주 중 최소 2개 범주가 필요하다. `[S1 §2, 기준일 2026-07-22]` | 자연인·법인·AI 에이전트 등 신청자 유형별 세부 구분은 미확인이다. |
| DID 변경 재등록 | DID 업데이트를 요청하면 1 NVC가 부과된다. `[S1 §3, 기준일 2026-07-22]` | VC 재제출 여부와 처리기간은 미확인이다. |
| 휴면 계정 재활성화 | 365일을 초과해 비활성 상태였던 계정의 재활성화 수수료는 2 NVC다. `[S1 §3, 기준일 2026-07-22]` | 비활성 기간의 기산점과 활동 판정 방식은 미확인이다. |

이 문서에서 사용하는 ‘지정’은 별도의 법적 지위가 아니라 검증 산출물의 마지막 단계인 ‘등록 확인’을 가리키는 편의상 표현이다. 별도 지정서·인증서 발급 여부는 **미확인**이다. `[V1, 기준일 2026-07-22]`

### 2.2 신청 전 자가진단

아래 질문에 모두 ‘예’라고 답할 수 있어야 확인된 KYC Level 2 요건을 충족한다.

1. 제출할 유효한 VC가 3개 이상인가? `[S1 §2; V1, 기준일 2026-07-22]`
2. VC 3개가 Education·Governance·Employment 가운데 최소 2개의 서로 다른 범주를 포함하는가? `[S1 §2, 기준일 2026-07-22]`
3. 본인의 신청 유형이 최초 등록, DID 변경 재등록, 365일 초과 비활성 계정 재활성화 중 어디에 해당하는지 구분했는가? `[S1 §3, 기준일 2026-07-22]`
4. 유료 유형이라면 적용 수수료와 납부 증빙을 준비했는가? `[S1 §3; V1, 기준일 2026-07-22]`
5. 이미 KYC Level 2인 경우 180일 만료일과 만료 전 30일 갱신 창을 확인했는가? `[S1 §2, 기준일 2026-07-22]`

판정은 단순하다. VC가 3개 미만이거나 인정 범주가 1개뿐이면 확인된 필수 요건을 충족하지 못한다. `[S1 §2, 기준일 2026-07-22]` 개별 VC의 인정 발급기관, 파일 형식, 원본·사본 구분, 진위 확인 방법은 **미확인**이므로 운영 주체에 사전 문의해야 한다. `[S1 기재 부재, 기준일 2026-07-22]`

### 2.3 등록 준비 항목

다음 표는 공식 요건을 누락 없이 정리하기 위한 실무용 작업표다. `발급자`, `VC 식별자`, `개별 만료일` 칸은 신청자가 진위·유효성을 스스로 점검하기 위한 관리 항목이며, 별도 공식 제출 필드로 확인된 것은 아니다.

| 순번 | VC 식별자 | 범주 | 발급자 | 개별 유효 여부·만료일 | 제출 준비 |
|---:|---|---|---|---|---|
| 1 |  | Education / Governance / Employment |  |  | ☐ |
| 2 |  | Education / Governance / Employment |  |  | ☐ |
| 3 |  | Education / Governance / Employment |  |  | ☐ |

준비 완료 기준은 `총 3개 이상`, `서로 다른 범주 2개 이상`, `유효성 확인`이다. `[S1 §2; V1, 기준일 2026-07-22]` 유료 신청에는 적용 수수료의 납부 증빙을 함께 준비한다. `[V1, 기준일 2026-07-22]`

### 2.4 단계별 신청·심사·등록 확인 절차

#### 1단계 — 신청·제출

VC 3개 이상을 제출하고, Education·Governance·Employment 중 최소 2개 범주가 포함되도록 구성한다. `[S1 §2; V1, 기준일 2026-07-22]` 수수료가 적용되는 신청 유형이면 납부 증빙을 함께 제출한다. `[V1, 기준일 2026-07-22]` 공식 접수 URL, 이메일, 화면 경로는 **미확인**이다. `[S1 기재 부재, 기준일 2026-07-22]`

#### 2단계 — 검증·심사

심사에서는 최소 VC 수량, 범주 다양성, 180일 유효기간 기준 및 해당 수수료를 확인한다. `[V1, 기준일 2026-07-22]` 정책 원문상 180일은 KYC Level 2 상태의 유효기간이며, 개별 VC에 동일한 180일 만료기간이 부여된다고 단정할 근거는 없다. `[S1 §2, 기준일 2026-07-22]`

#### 3단계 — 등록 확인

KYC Level 2 검증을 통과하면 등록 확인 단계로 진행한다. `[V1, 기준일 2026-07-22]` 확인서 형식, 통지 채널, 효력 발생 시점 및 별도 인증서 발급 여부는 **미확인**이다. `[S1 기재 부재, 기준일 2026-07-22]`

위 ‘미확인’ 항목은 제출을 요구한다는 뜻이 아니며, 접수처가 확인되면 필요 여부를 질의하기 위한 목록이다. `[S1 기재 부재, 기준일 2026-07-22]`

|---|---|---|

| 접수 후 심사기간 | 미확인 | 처리 SLA와 보완 기한을 운영 주체에 확인해야 한다. |
| KYC Level 2 유효기간 | 180일 `[S1 §2, 기준일 2026-07-22]` | 기산점은 원문에 명시되지 않았다. |

| 정기 KYC 갱신 | 수수료 미확인 | 신규 등록 무료 정책을 정기 갱신 무료로 확대 해석하지 않는다. |

NVC의 법정화폐 환산액, 네트워크·결제 부대비용, VC 발급비는 확인되지 않았다. 따라서 비용 예산은 위의 NVC 명목액까지만 확정하고 나머지는 별도 확인해야 한다. `[S1 기재 부재, 기준일 2026-07-22]`

### 2.7 등록 확인 후 의무

- KYC Level 2는 180일마다 만료되므로 만료 전 30일 이내에 갱신한다. `[S1 §2, 기준일 2026-07-22]`
- 갱신하지 않으면 KYC 상태가 Level 1으로 강등된다. `[S1 §2, 기준일 2026-07-22]`
- DID를 변경하면 재등록 수수료 1 NVC가 적용된다. `[S1 §3, 기준일 2026-07-22]`
- 계정이 365일을 초과해 비활성 상태가 된 뒤 재활성화하면 2 NVC가 적용된다. `[S1 §3, 기준일 2026-07-22]`

지속 모니터링 의무, 정기 보고, 변경 신고 기한, 자료 보관기간은 확인되지 않았다. `[V1 미확인 항목 및 S1 기재 부재, 기준일 2026-07-22]`

### 2.8 자주 발생할 수 있는 탈락·보완 사유

공식 탈락 사유 목록은 확인되지 않았다. 다만 아래 항목은 검증된 필수 기준을 충족하지 못해 탈락 또는 보완으로 이어질 수 있는 직접적인 요건 미충족 사례다. `[S1 §2-3; V1, 기준일 2026-07-22]`

| 점검 사유 | 조치 |
|---|---|
| VC가 3개 미만임 | 유효한 VC를 추가해 최소 3개를 맞춘다. `[S1 §2, 기준일 2026-07-22]` |
| VC는 3개 이상이나 범주가 1개뿐임 | Education·Governance·Employment 중 다른 범주의 VC를 추가한다. `[S1 §2, 기준일 2026-07-22]` |
| 세 범주 밖의 VC만으로 다양성 요건을 계산함 | 인정된 세 범주 안에서 최소 2개 범주를 다시 구성한다. `[S1 §2, 기준일 2026-07-22]` |
| 유료 유형인데 수수료 검증 또는 납부 증빙이 누락됨 | 신청 유형별 금액을 확인하고 납부 증빙을 보완한다. `[S1 §3; V1, 기준일 2026-07-22]` |
| KYC 만료 전 30일 갱신 창을 놓침 | Level 1 강등 가능성을 확인하고 갱신 절차를 문의한다. `[S1 §2, 기준일 2026-07-22]` |

### 2.9 문의처

담당 기관명, 부서, 이메일, 전화번호, 접수 포털은 정책 원문과 검증 산출물에서 확인되지 않았다. **문의처는 미확인**이다. `[S1 기재 부재; V1, 기준일 2026-07-22]`

신청 전 운영 주체에 아래 사항을 확인한다.

1. 공식 접수 채널과 신청서 서식
2. VC 인정 발급기관·형식·검증 방식
3. KYC 180일의 정확한 기산점
4. 접수 후 처리기간, 보완 횟수·기한, 결과 통지 방식
5. 정기 KYC 갱신 수수료와 납부 방식
6. 개인정보·VC 데이터 보관기간과 삭제 절차
7. 상충하는 두 `CITIZEN-REGISTRY.md` 중 현재 시행본

## 4. 한계·주의사항

1. **정책 파일 충돌**: 기준 출처 `[S1]`은 수수료를 `0/1/2 NVC`, 범주를 `Education/Governance/Employment`로 규정한다. 그러나 별도 경로의 확정 표기 문서 `[C1]`은 `1/10/5 NVC`, `Education/Governance/Labor`로 규정한다. 본 보고서는 사용자가 제공한 검증 통과 결과와 일치하는 `[S1]`만 적용했으며, 실제 시행본은 운영 주체의 확인이 필요하다. `[S1 §2-3; C1 §핵심 파라미터·제2조·제3조, 기준일 2026-07-22]`
2. **180일의 의미**: `[S1]`이 명시하는 180일은 KYC Level 2 상태의 만료 주기다. 모든 개별 VC의 유효기간이 180일이라고 확대 해석해서는 안 된다. `[S1 §2, 기준일 2026-07-22]`
3. **수수료의 의미**: 0/1/2 NVC는 각각 최초 등록, DID 변경 재등록, 365일 초과 비활성 계정 재활성화에 대응한다. 정기 KYC 갱신비는 확인되지 않았다. `[S1 §3, 기준일 2026-07-22]`
4. **미확인 범위**: 제품별 예외, 지속 검증 여부, 데이터 보관기간, 처리기간, 접수·문의 채널은 확인되지 않았다. `[V1 및 S1 기재 부재, 기준일 2026-07-22]`
5. **시행 여부**: 이 보고서는 정책·검증 기준을 정리한 것이며, API·화면·결제 기능의 실제 구현 또는 운영 상태를 보증하지 않는다. 구현 상태는 별도 검증이 필요하다. `[보고서 범위 한계, 기준일 2026-07-22]`
